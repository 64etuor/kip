# 용어집 (Glossary)

이 문서는 KIP을 처음 설치·운영하는 사람을 위한 것입니다. 다른 문서에서
어려운 단어를 만나면 여기부터 보세요. 각 항목은 "한 줄 뜻 → 왜 중요한지 →
실제로 언제 마주치는지" 순서입니다.

---

## 큰 그림

**KIP**
회사 문서(NAS 파일, 한글 HWP/HWPX, PDF, PPTX, 엑셀, 슬랙, 메일)를 모아
검색하고, 답변할 때 **근거가 되는 원문 위치를 함께 제시**하는 시스템입니다.
"검색되는 사내 자료 창고 + 근거 추적기"라고 생각하면 됩니다.

**근거 우선 (evidence-first)**
KIP은 "답"만 주지 않고 "이 답이 어느 파일 몇 페이지에서 나왔는지"를 항상
같이 줍니다. 그래서 사람이 원문을 열어 확인할 수 있습니다.

**에이전트 우선 (agent-first)**
사람이 GUI로 클릭하는 대신, AI 비서(에이전트)나 스크립트가 명령으로 쓰도록
설계되었습니다. 그래서 모든 출력이 사람이 읽는 문장이 아니라 기계가 읽는
JSON입니다.

---

## 설치·설정할 때 만나는 말

**워크스페이스 (workspace)**
자료를 담는 큰 서랍 이름입니다. 보통 회사/팀 단위로 하나면 충분합니다
(예: `default`). 서랍이 다르면 서로 검색되지 않습니다.

**소스 (source)**
KIP이 읽어올 자료의 출처 한 곳. 예를 들어 "NAS의 `/mnt/nas/과제문서` 폴더"가
소스 하나입니다. 슬랙 워크스페이스나 메일함도 소스가 될 수 있습니다.

**커넥터 (connector)**
소스에서 자료를 실제로 읽어오는 부품입니다. 파일 폴더용, 슬랙용, 메일용이
따로 있습니다. 사용자는 보통 "어떤 폴더를 읽을지"만 정하면 됩니다.

**읽기 전용 마운트 (read-only mount)**
KIP이 원본 폴더를 **절대 수정하지 못하도록** 읽기 전용으로만 연결하는 것.
KIP은 원본 파일을 고치거나 지우지 않습니다.

**ACL 스코프 (ACL scope)**
"이 자료를 누가 볼 수 있는가"를 나타내는 이름표입니다
(예: `workspace:default`). 검색할 때 KIP은 **먼저** 이 이름표로 걸러낸 뒤
찾기 때문에, 권한 없는 자료는 존재 자체가 보이지 않습니다.
잘 모르겠으면 설치 시 안내되는 기본값을 쓰면 됩니다.

**분류 (classification)**
자료의 민감도 등급(예: 공개/내부/제한). 외부 AI 모델에 내용을 보내도 되는지
판단할 때 쓰입니다.

**모델 egress (model egress) / 외부 전송 정책**
"문서 내용을 외부 AI 서비스로 보내도 되는가"에 대한 규칙입니다. 기본값은
보내지 않음입니다. 사내에서만 돌리려면 그대로 두면 됩니다.

**시크릿 참조 (secret ref)**
비밀번호·API 키를 설정 파일에 직접 적지 않고, "환경변수 이름"만 적어두는
방식입니다(예: `env:KIP_DATABASE_URL`). 실제 값은 파일에 남지 않습니다.

**CAS (content-addressed storage)**
원본 파일의 사본을 내용 해시 이름으로 보관하는 저장소 폴더입니다. 원본이
나중에 바뀌어도 "그때 그 내용"을 다시 확인할 수 있게 해 줍니다.

**플랜 지문 (plan fingerprint)**
설치 계획서의 지문(해시)입니다. 사용자가 승인한 계획과 실제로 적용되는 계획이
같은지 확인하는 용도라, 사용자는 값 자체를 이해할 필요가 없습니다.

## 자료가 들어올 때 일어나는 일

**동기화 / 인덱싱 (sync)**
소스 폴더를 훑어서 새 파일·바뀐 파일을 KIP에 반영하는 작업입니다.
`kip sync run --source 이름`으로 실행합니다. 검색할 때 자동으로 일어나지
않습니다(느려지지 않게 하려고 일부러 분리했습니다).

**파서 (parser)**
파일 형식별로 내용을 뽑아내는 부품입니다. 한글 파일용, PDF용, 엑셀용,
PPT용이 따로 있습니다.

**추출 (extraction)**
파서가 파일 하나에서 뽑아낸 결과 묶음입니다.

**섀도 추출 → 활성화 (shadow extraction / activation)**
파서를 새로 돌릴 때 결과를 **먼저 그늘(shadow)에 만들어 두고**, 문제가 없을
때만 기존 것을 대체합니다. 그래서 새 추출이 실패해도 이미 잘 되어 있던
자료가 망가지지 않습니다.

**증거 단위 (evidence unit / content unit)**
검색과 인용의 최소 조각입니다. 예: PDF 3페이지, 엑셀 `정산` 시트, 워드
문단 12~18, CSV 5~40행. 답변에 인용되는 단위가 바로 이것입니다.

**로케이터 (locator)**
증거 단위가 원문 어디인지 가리키는 좌표입니다(페이지 번호, 시트 이름,
문단 범위 등). "원문 확인" 버튼의 주소라고 보면 됩니다.

**품질 점수 (quality score)**
추출이 얼마나 잘 됐는지 0~1 점수입니다. 낮으면 글자가 깨졌거나 내용이 많이
빠졌다는 뜻이라, 낮은 결과는 색인에서 걸러낼 수 있습니다.

**원본 변경됨 (stale / source changed)**
색인한 뒤에 원본 파일이 바뀌었다는 표시입니다. KIP은 이 경우 그 근거를
인용하지 않고 경고합니다(오래된 내용으로 답하지 않기 위해서).

**툼스톤 (tombstone)**
원본이 삭제되었을 때 "여기 있던 자료는 삭제됨"이라고 표시만 남기는 것.
기록은 남기되 검색에서는 빠집니다.

## 검색·답변할 때 만나는 말

**렉시컬 검색 (lexical search)**
단어가 실제로 들어있는 문서를 찾는 방식(키워드 검색). KIP의 기본입니다.

**시맨틱/벡터 검색 (semantic search)**
단어가 달라도 뜻이 비슷하면 찾는 방식. 품질 검증을 통과할 때까지 기본
비활성입니다.

**리랭커 (reranker)**
1차로 찾은 후보들을 질문과 더 잘 맞는 순서로 다시 정렬하는 부품입니다.

**컨텍스트 팩 (context pack)**
질문에 답하기 위해 모은 근거 묶음입니다. 크기 상한이 있어 무한정 커지지
않습니다.

**추상(회피) / 거부 (abstain / refusal)**
근거가 부족하거나 숫자를 정확히 확인해야 하는 상황에서 KIP이 **일부러 답을
하지 않는 것**입니다. 예: 엑셀 합계는 얕은 색인 대신 원본 셀 범위를 직접
읽어야 하므로 먼저 거부하고 `xlsx-read`를 요구합니다. 오답보다 낫습니다.

**봉투 (envelope)**
모든 명령의 출력 JSON을 감싸는 공통 껍데기입니다. `ok`(성공 여부),
`data`(결과), `error`(오류 코드/메시지), `meta`(요청 ID) 형태라 스크립트가
결과를 일관되게 처리할 수 있습니다.

## 온톨로지 (지식 관계) 관련

**온톨로지 (ontology)**
"이 회사에서 쓰는 개념과 관계의 사전"입니다. 예: `과제`, `협약서`라는 개념과
"이 문서가 저 과제에 속한다"는 관계 종류를 정의합니다. `ontology/` 폴더의
YAML 파일이 그 사전이며, 여기 없는 개념·관계는 시스템이 사실로 인정하지
않습니다.

**엔티티 (entity)**
사전에 정의된 개념의 실제 사례. 예: 개념은 `과제`, 엔티티는 `A과제`.

**프레디킷 (predicate) / 관계**
두 대상을 잇는 관계 종류. 예: `belongs_to_project`(과제에 속함),
`amends`(일부 변경함).

**어서션 (assertion)**
"A문서가 B과제에 속한다"처럼 **승인된 사실 한 줄**입니다.

**후보 (candidate)**
아직 승인되지 않은 제안입니다. AI가 뽑아낸 관계는 전부 후보로 들어오고,
사람이 승인해야 어서션(사실)이 됩니다. 이 구분이 KIP 신뢰성의 핵심입니다.

**리뷰 / 승인 / 철회 (review / approve / revoke)**
후보를 사람이 확인해 승인하거나 거절하는 절차. 승인된 사실도 나중에
철회할 수 있습니다. 온톨로지를 바꾸는 명령은 **관리자 역할**이 필요합니다
(`--role admin` 또는 `KIP_ROLES=admin`).

**자동 승인 정책 (auto-approve policy)**
위험도가 낮은 관계에 한해, 사람 심사 실적(정밀도)이 충분히 쌓였을 때만
자동 승인하는 선택 기능입니다. **기본은 꺼짐**이며, 켜더라도 모든 자동 승인은
표시되고 철회할 수 있습니다.

## 저장·운영 관련

**프로젝션 (projection)**
원본 데이터로부터 다시 만들 수 있는 보조 색인입니다(검색 색인, 벡터 색인,
그래프). 망가지면 지우고 다시 만들면 되므로, 백업의 핵심은 아닙니다.

**정본 저장소 (canonical store)**
진짜 원장인 PostgreSQL 데이터베이스. 백업해야 하는 대상은 이것과 CAS입니다.

**잡 (job) / 워커 (worker)**
시간이 걸리는 작업(동기화, 관계 채굴 등)을 대기열에 넣고 백그라운드에서
처리하는 구조입니다. `kip jobs list`로 상태를 봅니다.

**마이그레이션 (migration)**
데이터베이스 구조를 바꾸는 스크립트입니다. `./scripts/migrate.sh`로 적용하며,
한 번 배포된 마이그레이션은 절대 수정하지 않고 새로 추가합니다.

**MCP**
AI 클라이언트(예: Claude Desktop)가 KIP 기능을 도구처럼 쓰게 해 주는
연결 규격입니다. CLI·REST와 같은 내부 로직을 씁니다.

**골든셋 / 평가 게이트 (golden set / evaluation gate)**
검색 품질을 재기 위한 정답지와, 그 점수가 기준에 못 미치면 새 설정을
활성화하지 못하게 막는 장치입니다.
